# 作战手册

先从当前仓库的 AGENTS.md 和 README 定位开发指南、架构与契约，确认本次任务范围、当前代码和用户已有修改。技能内的链接相对本技能文件；执行项目命令时使用目标仓库要求的工作目录。

## 分类路由

每次任务读 [尽早暴露错误](../principle-fail-early/SKILL.md) 和 [取得真实反馈](../principle-real-feedback/SKILL.md)。再按当前要做的决策选择下面的分类，在分类表中只读取命中触发条件的原则或工作流技能。

| 当前要做什么 | 从哪里选择原则 |
| --- | --- |
| 判断完成条件、功能取舍或备选方案 | [目标与方案](references/goals-and-design.md) |
| 设计状态、接口、输入校验、恢复或并发 | [模型与边界](references/models-and-boundaries.md) |
| 新增能力、重构、迁移或批量修改 | [实现与迁移](references/implementation-and-migration.md) |
| 定位失败、修改测试或判断性能与评估结果 | [诊断与验证](references/diagnosis-and-verification.md) |
| 等待用户、交接与过程记录、控制上下文或沉淀经验 | [协作与维护](references/collaboration-and-maintenance.md) |

任务可以跨类。先处理会阻断后续的判断，出现新的失败或设计问题时重新路由；不因为进入一类就加载该类全部内容。用户点名原则或技能时直接读取它。交付时说明实际改变的决策和证据，不逐条汇报已读名称。

## 推进任务

先确定用户会观察到的完成条件，以及最值得先验证的一项假设。取得最小反馈，再扩展实现。

- 修改运行行为时，对照当前仓库的架构和实际入口；涉及状态、计量、隔离或恢复时，定位负责该契约的设计与验收用例。
- 外部集成和性能工作先运行最小探针、校准测量口径，依据结果决定后续实现。
- 审查或调研任务先给出可定位的问题、证据和修正建议；用户要求实施时再修改代码。
- 已授权的实施持续推进到实现、验证和交付。碰到阻碍时完成不依赖它的工作，并说明缺失的具体条件。

修改完成后，按当前仓库的开发指南执行所需验证，读取本次实际输出和产物。检查当前 diff、受影响调用方和失败路径；交付行为变化、实际结果及剩余问题。

维护手册时，从真实失败或重复需求修订现有原则，再更新对应分类；项目命令和协议由使用手册的仓库维护。追溯上游或调整分类时读 [pstack 吸收映射](references/pstack-map.md)。
