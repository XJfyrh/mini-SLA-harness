# 展示工作依据

普通任务沿用提交和验证输出。需要保留会改变方向的选择、阶段衔接、失败转向或交接信息时建立日志，只补充已有产物无法表达的取舍与未决事项。用户直接要求记录过程时，从当前任务开始使用本技能。

## 建立记录

一个任务保留一份主日志，放在仓库约定的忽略产物目录。每个执行会话使用稳定的 `run_id`；新会话接手同一日志时先读末尾记录，以 `start` 行说明接手范围、当前源码身份与未决事项。同一会话恢复时沿用原标识；若期间另一会话写过，先追加新的 `start` 行标明接手位置。

每份日志由一个执行者写入。并行工作各写自己的文件，主日志引用子任务日志及实际产物。需要长期随代码审查的记录，按仓库文档约定保存；原始运行输出继续使用产物目录。

使用标准库辅助脚本 [log.py](scripts/log.py)，自动生成 UTC 时间和表头，追加 UTF-8 TSV。以下命令中的路径相对技能所在仓库，日志路径与证据路径由当前任务确定：

```text
python .agents/skills/show-me-your-work/scripts/log.py artifacts/audit/task.tsv --run task-session-1 --phase start --decision "开始检查任务入口" --why "先确定当前行为与失败边界" --evidence "HEAD=<实际提交>; <任务说明或已读文件位置>" --result "待验证"
```

写入前把示例中的证据替换成已核实的位置。字段值以 `-` 开头时使用 `--字段=值` 形式，避免被当成另一个选项。新增记录成功后输出 `日志路径:行号`。表头不符、记录损坏、空字段或未声明接手时，脚本失败并保留原日志。

## 写什么

一行对应一个关键决策或检查点，字段为：

| 字段 | 内容 |
| --- | --- |
| `ts` | 实际记录时间，由脚本生成 |
| `run_id` | 本次执行会话标识，跨轮次保持一致 |
| `phase` | 当前阶段；`start` 专用于开始或接手 |
| `decision` | 选择了什么或实际做了什么 |
| `why` | 改变这项决策的事实或取舍，简短说明 |
| `evidence` | 可定位的文件、日志行、提交或链接；本地路径以仓库根目录为基准 |
| `result` | 已观察结果；未执行或未完成时明确写“待验证”等状态 |

证据直接指向原始输出与可检查产物，能复跑的检查同时保留命令、输入和源码身份。已有验证报告时引用它，不抄写一份平行结果。补记较早发生的事情时说明补记范围，不能把当前生成时间说成当时的执行时间。

日志只追加。错误结论用新行指明被更正的行号、事实和新证据；失败、撤回与未知结果也保留。不要把计划写成完成，或在后续验证通过后修改此前的失败记录。脚本保证记录格式，证据是否支持结论由执行者核验。

## 交付前核对

逐项核对本次记录的结论与证据：结论是否相符、源码是否一致、失败和转向是否遗漏。已读取且未变化的证据可直接复用；证据变化或结论存疑时打开原始材料核查。会话记录可取得时只读取当前任务对应的记录；缺失材料保留为未核实，不从其他会话补造依据。

发现问题就追加更正或补齐实际验证。复杂或重要改造需要独立复核且已有授权时，给复核者日志与原始证据，请其指出无证据结论、漏验和高影响取舍；只有真正执行后才记录复核者与结果。

交付给出主日志位置、关键结果及仍需关注的具体问题，每项指向相应记录或产物。其他技能需要过程记录时路由到这里，共用格式与脚本。
